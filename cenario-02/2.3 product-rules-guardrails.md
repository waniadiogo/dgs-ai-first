## Product Rules & Guardrails (Product Specialist)

> **Escopo:** Esta seção define o comportamento esperado do assistente NovaTech em produção, os contratos semânticos do domínio de logística e as restrições que afetam a geração de código. É consumida por agentes de IA, pipelines de CI e revisores humanos.
>
> **Responsável:** Product Specialist
> **Última atualização:** 2024-01
> **Referência de especificação:** `specs/query-endpoint/requirements.md`

---

### 1. Regras de Comportamento do Assistente

#### 1.1 Obrigações (DEVE)

```
RULE-001  O assistente DEVE citar a fonte em toda resposta, incluindo:
          - Identificador do documento (ex.: POL-001, PROC-042-v2, SLA-2024)
          - Seção específica (ex.: seção 3.1, tabela da seção 2.1)
          Formato mínimo aceitável: "[POL-001 § 3.1]"

RULE-002  O assistente DEVE incluir o campo `source_document` no JSON de retorno
          em toda resposta, mesmo quando a confiança for baixa.
          Estrutura obrigatória:
            {
              "source_document": {
                "id": "<identificador>",
                "section": "<seção>",
                "version": "<versão do documento>"
              },
              "confidence": "high" | "medium" | "low"
            }

RULE-003  O assistente DEVE responder em português formal (norma culta brasileira).
          Contrações informais, gírias e abreviações não são permitidas nas respostas
          ao usuário final.

RULE-004  Quando duas versões de um mesmo documento existirem no corpus (ex.:
          PROC-042 v1 e PROC-042-v2), o assistente DEVE:
          a) Utilizar os dados da versão mais recente como resposta principal.
          b) Informar explicitamente ao usuário que existe uma versão anterior.
          c) Aplicar as disposições transitórias quando especificadas no documento
             (ex.: PROC-042-v2 § 5: chamados abertos antes de 01/12/2023 usam v1).

RULE-005  O assistente DEVE escalar ao supervisor quando não encontrar base
          documental suficiente para responder com confiança alta ou média.
```

#### 1.2 Proibições (NÃO DEVE)

```
RULE-006  O assistente NÃO DEVE gerar valores numéricos (prazos, multiplicadores,
          percentuais, SLAs) que não estejam literalmente presentes na documentação
          indexada. Interpolação, arredondamento ou estimativa de valores numéricos
          são proibidos.
          Exemplos de valores que DEVEM vir literalmente do corpus:
          - Multiplicadores regionais de frete (PROC-042-v2 § 2.1)
          - Prazos de SLA por tier (SLA-2024 § 2)
          - Percentuais de seguro de carga (referenciados no FAQ-Atendimento item 22,
            mas NÃO validados — ver RULE-012)
          - Prazos de devolução (POL-001 § 3.1)

RULE-007  O assistente NÃO DEVE afirmar que carga perigosa (classes 1 a 6 da ANTT,
          conforme Resolução ANTT nº 5.947/2021) pode ser devolvida pelo processo
          padrão. A resposta correta é sempre encaminhar ao ramal 4500 (Gestão de
          Riscos) para tratamento individual.
          Base normativa: POL-001 § 3.2

RULE-008  O assistente NÃO DEVE inventar ou confirmar tiers de cliente além dos
          três oficialmente definidos: Gold, Silver e Standard.
          Se o cliente mencionar "Platinum" ou qualquer outro tier, o assistente
          DEVE informar que esse tier não existe e orientar a verificar o contrato.
          Base normativa: SLA-2024 § 1 (nota explícita sobre ausência de outros tiers)

RULE-009  O assistente NÃO DEVE utilizar o FAQ-Atendimento como fonte normativa
          primária. Esse documento é classificado como informal e não validado por
          Compliance (ver cabeçalho do FAQ-Atendimento). Pode ser usado apenas como
          contexto operacional secundário, sempre com indicação da limitação.

RULE-010  O assistente NÃO DEVE fornecer informações sobre seguro de carga (percentuais)
          sem alertar que os valores variam por contrato e que o Comercial deve ser
          consultado para contratos anteriores a 2023.
```

#### 1.3 Tratamento de Incerteza (QUANDO EM DÚVIDA)

```
RULE-011  QUANDO EM DÚVIDA sobre a confiança da resposta, o assistente DEVE:
          a) Prefixar a resposta com aviso explícito:
             "⚠️ Aviso: esta resposta possui confiança baixa. Recomenda-se
              confirmação com o supervisor ou na documentação normativa."
          b) Definir `"confidence": "low"` no campo JSON de retorno.
          c) Sugerir escalação ao supervisor.

RULE-012  QUANDO duas versões de documento coexistirem sem hierarquia formal
          declarada no sistema (ex.: PROC-042 v1 e v2 sem status de obsolescência),
          o assistente DEVE:
          a) Usar a versão com data de emissão mais recente como referência principal.
          b) Informar ao usuário a situação de ambiguidade documental.
          c) Não mascarar a contradição — expô-la é parte da resposta correta.

RULE-013  QUANDO o usuário perguntar sobre carga perigosa em qualquer contexto
          (devolução, frete, rastreamento), o assistente DEVE verificar ativamente
          se a resposta envolve restrições das RULE-007 antes de responder.
```

### 2. Glossário de Linguagem Ubíqua do Domínio

> Termos canônicos usados no corpus documental, no código e nas respostas do assistente. Qualquer divergência de nomenclatura em código, prompts ou testes deve ser tratada como bug.

| Termo | Definição | Fonte |
|---|---|---|
| **CT-e** | Conhecimento de Transporte Eletrônico — documento fiscal obrigatório para cada operação de transporte. Chave de identificação de chamados de devolução. | POL-001 § 3.3 |
| **Tier** | Classificação do cliente: `Gold`, `Silver` ou `Standard`. Determina SLAs contratuais. Não existem outros valores válidos. | SLA-2024 § 1 |
| **Frete especial** | Frete aplicável a cargas acima de 500kg, calculado com multiplicadores regionais e fator de peso. Regido pela PROC-042. | PROC-042-v2 § 1 |
| **Multiplicador regional** | Fator numérico aplicado por região de destino no cálculo do frete especial. Valores vigentes em PROC-042-v2 § 2.1. | PROC-042-v2 § 2.1 |
| **Fator de peso** | Fator numérico aplicado conforme faixa de peso da carga no cálculo do frete especial. | PROC-042-v2 § 2 |
| **Incidente crítico** | Chamado que atende a pelo menos um critério de criticidade definido em SLA-2024 § 3. Possui SLAs de atendimento reduzidos. | SLA-2024 § 3 |
| **SLA de resposta** | Prazo máximo para o primeiro retorno ao cliente após abertura do chamado. | SLA-2024 § 2 |
| **SLA de resolução** | Prazo máximo para encerramento efetivo do chamado. | SLA-2024 § 2 |
| **Carga perigosa** | Carga classificada nas classes 1 a 6 da ANTT (Resolução nº 5.947/2021). Sujeita a restrições de devolução e frete. | POL-001 § 3.2 |
| **Coleta reversa** | Operação de logística reversa agendada pela NovaTech após aprovação de devolução. | POL-001 § 3.3 |
| **Disposições transitórias** | Regras de migração entre versões de documento para chamados em processamento. | PROC-042-v2 § 5 |
| **Chunk** | Fragmento de documento indexado no corpus de recuperação RAG. Unidade mínima retornada pelo serviço de busca. | `data/retrieval-corpus/` |
| **source_document** | Campo obrigatório no JSON de resposta do assistente, identificando a origem normativa da informação. | RULE-002 |
| **Gestão de Riscos** | Setor responsável por tratamento individual de cargas perigosas e exceções à política de devolução. Ramal 4500. | POL-001 § 3.2 |

### 3. Restrições que Impactam a Geração de Código

> Estas restrições DEVEM ser aplicadas em revisões de código, prompts do sistema, testes e pipelines de CI. Qualquer código que viole estas regras DEVE ser bloqueado no PR.

#### 3.1 Contrato do campo `source_document`

```typescript
// OBRIGATÓRIO: toda resposta do assistente DEVE incluir source_document.
// NÃO É OPCIONAL mesmo quando confidence === 'low'.
interface AssistantResponse {
  answer: string;
  source_document: {
    id: string;        // Ex.: "PROC-042-v2", "POL-001", "SLA-2024"
    section: string;   // Ex.: "§ 2.1", "seção 3.3", "tabela § 2"
    version: string;   // Ex.: "2.0", "3.1", "2024.1"
  };
  confidence: 'high' | 'medium' | 'low';
  low_confidence_reason?: string; // Obrigatório quando confidence === 'low'
}
// Fonte: RULE-002
```

#### 3.2 Enumeração de tiers de cliente

```typescript
// SOMENTE estes três valores são válidos. Nunca adicionar novos sem
// aprovação explícita do Product Specialist e atualização de SLA-2024.
type CustomerTier = 'Gold' | 'Silver' | 'Standard';
// Fonte: RULE-008, SLA-2024 § 1
```

#### 3.3 Enumeração de classes de carga perigosa

```typescript
// Classes que bloqueiam o fluxo de devolução padrão (POL-001 § 3.2).
// Qualquer lógica de elegibilidade de devolução DEVE verificar esta lista.
const DANGEROUS_CARGO_CLASSES = [1, 2, 3, 4, 5, 6] as const;
type DangerousCargoClass = typeof DANGEROUS_CARGO_CLASSES[number];
// Fonte: RULE-007, POL-001 § 3.2
```

#### 3.4 Proibição de geração de valores numéricos sem fonte

```typescript
// NÃO DEVE existir no código nenhum valor hardcoded de:
// - multiplicadores regionais (usar SOMENTE os valores de PROC-042-v2 § 2.1)
// - fatores de peso (usar SOMENTE os valores de PROC-042-v2 § 2)
// - prazos de SLA (usar SOMENTE os valores de SLA-2024 § 2)
// - prazos de devolução (usar SOMENTE os valores de POL-001 § 3.1)
//
// Todo valor numérico de domínio DEVE ser lido do corpus indexado,
// não inferido ou calculado pelo modelo.
// Fonte: RULE-006
```

#### 3.5 Seleção de versão de documento

```typescript
// Quando o corpus retornar chunks de múltiplas versões do mesmo documento,
// a lógica de seleção DEVE:
// 1. Preferir a versão com `version` numericamente mais alta.
// 2. Aplicar disposições transitórias quando presentes no documento.
// 3. Expor a ambiguidade ao usuário via campo `version_conflict` na resposta.
interface VersionConflict {
  document_id: string;       // Ex.: "PROC-042"
  versions_found: string[];  // Ex.: ["1.0", "2.0"]
  version_used: string;      // Ex.: "2.0"
  transitional_rule?: string; // Ex.: "Chamados anteriores a 01/12/2023 usam v1"
}
// Fonte: RULE-004, RULE-012, PROC-042-v2 § 5
```

#### 3.6 Restrição de uso do FAQ como fonte primária

```
// O FAQ-Atendimento NÃO DEVE ser indexado como documento normativo.
// Se incluído no corpus, DEVE ser marcado com metadata:
//   { "document_type": "informal", "normative": false }
// O prompt-builder NÃO DEVE apresentar chunks do FAQ como fonte autoritativa.
// Fonte: RULE-009, cabeçalho do FAQ-Atendimento
```
